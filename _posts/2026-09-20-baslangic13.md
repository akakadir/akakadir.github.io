siteye ufak bi şey eklemek istedim.

logonun yanında küçük bir konuşma balonu olacak, içinde de instagram biyografim olacak. kullanıcı açısından bakınca hiçbir numarası olmayan bi özellik. iki satır text işte.

ilk birkaç dakika gayet normal. sonra instagram'ın html'ine biraz daha dikkatli bakınca insan biraz hayatı sorguluyor. bi yerde component, başka yerde script, onun altında json, arada meta tag. aradığın bilgi de bunların arasında bi yerlerde takılıyor.

bi süre instagram'ın react componentiyle küfürleşiyorum.

component sakin.

ben değilim.

neyse. `og:title`, `description`, `og:image` gibi meta veriler zaten profil hakkında yeterince şey söylüyor. isim, biyografi, takipçi takip edilen cart curt hepsi geliyor.

güzel.

şimdi bunu sitemden çağırayım dedim.

cors çıktı.

web geliştirirken bazı problemler vardır, görünce şaşırmazsın. sadece tekrar karşılaşmış olmanın verdiği o hafif rahatsızlık gelir. cors da öyle.

işi gücü bırakıp küçük bi flask api yazdım. username geliyor, servis instagram profilini çekiyor, html parse ediyor, ayıklayıp json döndürüyor.

ilk halini render üzerinde çalıştırdım.

buraya kadar her şey okey.

sonra render'ın ücretsiz servisleri fazla barzo çıktı.

site açılıyor, request gidiyor, cevap gelmesini bekliyorsun. gelmiyor.

ilginç.

insan kendi sitesinde timeout yiyince hoş olmuyo. önce koda sonra loga bakıyo. ee sorun ne amk?

ani bi kararla flask'ı kendi bilgisayarımda `127.0.0.1:5000` üzerinde ayağa kaldırdım. localde zaten güzel çalışıyor. problem şu ki `127.0.0.1`'in dış dünyayla fazla bi tanışıklığı yok.

tailscale ile dışarı açtım, funnel üzerinden https endpoint aldım.

artık benim bilgisayarda çalışan flask servisine internetten ulaşılabiliyor.

buraya kadar hâlâ işin bi mantığı var.

sonra endpointimin kamuya açık olduğunu hatırladım.

insan bazı şeyleri yaptıktan sonra yaptığı şeye ikinci kere bakıyor.

“bunu kim çağırabiliyor?”

güzel soru.

flask tarafına internal secret ekledim. gelen isteğin doğru origin'den gelmesini bekliyor, bi de `X-Internal-Secret` header'ı doğru olacak. secret kodun içinde değil, environment variable'da.

doğrudan tailscale adresine gidip secret olmadan deniyorum.

403.

olması gereken bu.

sonra origin tarafını kurcaladım. çünkü `Origin` header'ını curl ile elle yazabiliyorsun.

yani isteyen:

benim adımla selam verebiliyor.

internet biraz tuhaf bi yer.

dolayısıyla origin kontrolü tek başına güvenlik değil. asıl önemli olan internal secret'ın tarayıcıya hiç düşmemesi.

secret'ı frontend'e koyarsan artık secret değildir. bunu ispatlamak için ayrıca uğraşmaya gerek yok.

siteyi doğrudan tailscale'e bağlamadım. araya cloudflare worker koydum.

böylece tarayıcı yalnızca worker'ı görüyor. worker arka tarafta tailscale'e gidiyor, gerekli secret'ı ekliyor, flask isteği alıyor, instagram'a çıkıyor.

şimdilik güzel.

sonra worker'ın public olduğunu hatırlıyorsun.

tabii public olacak.

yoksa site nasıl çağıracak.

dolayısıyla worker'a gelen isteğin ayrıca doğrulanması gerekiyor. turnstile'ı buraya koydum. site token alıyor, worker token'ı cloudflare'a doğrulatıyor. geçerliyse request devam ediyor.
